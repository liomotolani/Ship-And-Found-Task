| Field | Why it's needed | What VetReply does with it | What happens if the user gets it wrong |
|-------|-----------------|----------------------------|----------------------------------------|
| Full name | Identifies who the account belongs to. | Trimmed, then saved as the name on the user account (`server/actions/sign-up.ts`, line 69). The name is used in the dashboard and emails sent to users| The account is saved under the wrong name. The user can still confirm their email and sign in, because the name isn't used for either.It will display a dashboard with a wrong user name and also in the welcoime email it will display the wrong name |
| Email address | It's how the user signs in, and the only way VetReply can reach them for account emails. | Trimmed and lowercased (`lib/validation/sign-up.ts`, lines 11 to 13), saved on the account, and sent a confirmation link that expires after 1 hour (`lib/auth.ts`, lines 58 to 75). Password reset links are also sent to it (lines 23 to 37). | The confirmation link goes to the wrong address. Email verification is required (`lib/auth.ts`, line 19), so the user can't confirm the account and can't sign in, and a password reset link would go to the wrong address too. If the wrong address belongs to someone else, that person receives the confirmation email. |
| Password | Proves the person signing in is the account owner. | Must be at least 12 characters, checked in the form (`SignUpForm.tsx`, line 143), the server schema (`lib/validation/sign-up.ts`, line 24) and Better Auth (`lib/auth.ts`, line 20). Handed to Better Auth to create the account. | There's no confirm field, so a typo isn't caught at sign-up. The user won't be able to sign in with the password they think they set, and has to use "Forgot password". The reset link expires after 1 hour (`lib/auth.ts`, line 21). |
