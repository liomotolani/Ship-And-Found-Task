# Field justification

Every field on the VetReply sign-up form (`/auth?form=signup`), with three
questions each. Any field that failed all three would come out.

| Field | Why it's needed | What VetReply does with it | What happens if the user gets it wrong |
|-------|-----------------|----------------------------|----------------------------------------|
| Full name | Identifies who the account belongs to. | Trimmed, then saved as the name on the user account (`server/actions/sign-up.ts`, line 75). It is shown on the user's dashboard and used in emails sent to them. | The account is saved under the wrong name, so the dashboard and emails show the wrong name. It doesn't stop the user confirming their email or signing in, because neither uses the name. |
| Email address | It's how the user signs in, and the only way VetReply can reach them for account emails. | Trimmed and lowercased (`lib/validation/sign-up.ts`, lines 13 to 15), saved on the account, and sent a confirmation link that expires after 1 hour (`lib/auth.ts`, lines 58 to 75). Password reset links are also sent to it (lines 23 to 37). | The confirmation link goes to the wrong address. Email verification is required (`lib/auth.ts`, line 19), so the user can't confirm the account and can't sign in, and a password reset link would go to the wrong address too. If the wrong address belongs to someone else, that person receives the confirmation email. |
| Password | Proves the person signing in is the account owner. | Must be at least 12 characters, checked in the form and the server schema (`lib/validation/password.ts`, line 10) and by Better Auth (`lib/auth.ts`, line 20). Handed to Better Auth to create the account. | There's no confirm field, so a typo isn't caught at sign-up, although the show-password toggle lets the user check what they typed. If they still get it wrong, they can't sign in with the password they think they set, and have to use "Forgot password". The reset link expires after 1 hour (`lib/auth.ts`, line 21). |
| Membership number | Links the account to the user's membership with the practice. Users who don't know it can check with the receptionist. | Required in the form and the server schema (`lib/validation/sign-up.ts`, lines 22 to 25). It is **not yet saved** with the user: the call that creates the account only passes name, email and password (`server/actions/sign-up.ts`, lines 73 to 81). This is Defect 2 in `defects.md`. | Today, nothing, because it isn't saved. Once it is saved, a wrong number would link the account to the wrong membership. |
| Terms acceptance | The user must agree that staff review every reply, that VetReply is not an emergency service, that they are 18 or over, and how pricing works, before using it. | Required in the form and the server schema (`lib/validation/sign-up.ts`, lines 26 to 31). Like the membership number, it is **not yet saved** with the user (`server/actions/sign-up.ts`, lines 73 to 81). | The user can't sign up without ticking it. The form shows "Please confirm that you have read and agree to the terms and conditions." and moves focus to the checkbox. |

## Fields removed
The separate "I am 18 or over" checkbox was removed. The age requirement is
now part of the terms the user accepts: "You must be 18 or over, keep your
account secure, and use VetReply lawfully."
